# Submission

**Story:** describe what you sell, review one billing configuration, accept payment, and see correct records in your own application database. Show
the whole product, not the number of integrations.

## Evidence per judging criterion

The five criteria have equal weight; implementation is first in tie-breaking. This is an evidence plan, not a prediction of scores.

| Criterion | Proposed evidence |
|---|---|
| Implementation | Real PayPal flows, verified observations, recurring and credit rules, independent delivery, useful AI tools |
| Design | Clear setup, reviewed schema, understandable statuses, small SDK, helpful next actions |
| Impact | Specific developer problem, independent install, actual setup observations, genuine feedback |
| Innovation | Explain the combination and acknowledge existing tools; show the workflow advantage |
| Presentation | Coherent end-to-end functionality; test data and faults labelled honestly |

## Video (under 3 minutes)

| Time | Screen evidence |
|---|---|
| 0:00–0:15 | Problem and merchant app |
| 0:15–0:45 | AI drafts config; developer reviews schema, prices and generated flow |
| 0:45–1:15 | Real PayPal sandbox checkout and completed payment |
| 1:15–1:40 | Source records and the actual independent database update |
| 1:40–2:05 | Subscription access and credit consumption |
| 2:05–2:35 | Labelled target failure, evidence and delivery retry |
| 2:35–2:55 | SDK, MCP, self-host path, actual scope and value |

Record actual behaviour; label edits and don't imply a continuous benchmark. Supply reproducible evidence for flows that don't fit the video. Extra
integrations, fake metrics or untested features don't make a stronger entry.

## Checklist

Public source repo, assets and reproducible instructions; open-source license; working hosted demo or full local setup; public YouTube video under three
minutes; English materials; explanation of AI usage; accurate capability matrix.

Provide free judge access through the judging period. State the tested commit, test environment, access route and limits. Keep secrets out of the repo, video
and collections. Freeze the judged release at the deadline and avoid substantive later changes.
